# Clay Lab — the authoring contract

This file is rules and commands. The reasons live in
`plugins/clay_lab/README.md`; the blocks in `references/catalog.md`
(generated from the kernel's qdoc — the file it names beside each block is
the full doc); the traps in `references/pitfalls.md`, which you read
**before writing any 3D/QML lab code**. A lab is composed from those blocks,
never written from scratch, and every claim it makes is verified before
handover.

Three properties, all mandatory: **deterministic** (same seed + same stepped
frames ⇒ identical probe series), **agent-operable** (everything a user can
do is reachable through `eval` via the conventions below), **teaching-first**
(the lesson is in the app, not only in the paper).

## Definition of done

`labs/<slug>/` is finished when `tools/lab-check/lab-check labs/<slug>`
(ctest `lab_check_<slug>`) is green and the tier the lab declares in
`lab-check.json` (`"purpose"`) is complete:

| purpose | owes, on top of the common base |
|---|---|
| **research** — you are measuring something | `studies/<slug>/study.md` + committed records + the answerability table; no flow, no DE, no board owed |
| **teaching** — you are explaining it to someone | at least one flow with `expect`s, EN + DE narration, a storyboard `overview.grafli` |
| **learning** — you are working it out | a `paper.md` study path and a concept-map `overview.grafli` |

Common base, every tier: `Sandbox.qml` (root `id: root`, generated by
`lab-new`), `strings.js` (EN at least, from the first commit), `paper.md`,
`records/make.sh` with `--verify`, `figures/make.sh`, `lab-check.json`, the
determinism contract, and a `qmldir` in every directory the lab imports
(including its own — a directory cannot be listed over HTTP). Until #209
lands, `lab-check` still requires EN + DE key parity and a flow or a
`flowsReason` for every purpose. The three tiers and what their papers
and boards look like: `references/triad.md`. Flows: `references/flows.md`.

## Bootstrap

1. `git submodule update --init --recursive`, then `cmake --preset default`
   (Qt via `CMAKE_PREFIX_PATH`), `cmake --build --preset default`.
2. Build targets are QML module names: `ClayLab`, never `clay_lab`. After
   touching **any** plugin QML, build everything — plugin QML is baked into
   the plugin's resources; a target build or a reload keeps the old file live.
3. `clayrender` needs a real GUI session (never `QT_QPA_PLATFORM=offscreen`);
   never start or kill a dojo the person may be sitting in front of.
4. A new lab starts from the generator, never from a blank file or a copy:

   ```bash
   tools/lab-new/lab-new <slug> --kind build|continuous|draw --purpose learning|teaching|research
   ```

## Layout and boundaries

```
plugins/clay_lab/            the kernel (import Clayground.Lab)
labs/kits/<domain>/          domain kits: pure-JS model + QML visuals + strings.js + README (model card)
labs/<lab>/                  one lab = one situation; records/, figures/, studies/<slug>/
```

- Labs are not CMake targets. Run them: `./build/bin/claydojo --sbx
  labs/<lab>/Sandbox.qml`; headless, `QT_QPA_PLATFORM=offscreen
  ./build/bin/clayliveloader --sbx …`. Launch either with
  `QT_DISABLE_SHADER_DISK_CACHE=1`.
- **Kit vs lab.** The kit owns the domain (solver, part visuals, symbols,
  vocabulary); the lab owns the situation (UI, scenarios, narration, keys).
  Test: could a second lab use this kit without editing it? A kit graduates
  to `plugins/clay_<domain>/` once ≥ 2 labs use it unchanged.
- **Kit model code is pure JS** (`.pragma library`, no Qt types, no clock,
  no randomness of its own) with a node unit suite beside it
  (`labs/kits/traffic/traffic.test.js` is the shape), registered in
  `labs/CMakeLists.txt` with `clay_add_node_test`. A lab whose model has no
  kit yet keeps `<name>.js` + `<name>.test.js` beside `Sandbox.qml` and
  registers the suite the same way.
- Reference labs, in reading order: `labs/sensor-fusion-101/` (continuous
  3D), `labs/electronics-101/` (build lab, richest conventions),
  `labs/street-network-101/` (draw → derive → simulate, research study).

## Composition recipe

Work in this order; each step has a verification before the next.

1. **World + clock.** `SimClock { seed; sampleInterval }` is the only source
   of time and randomness. Step per frame (`fixedStep` + `onStepped`), never
   in lumps.
2. **Domain model** in the kit as pure JS; its node suite now, not later.
3. **Kernel wiring.** `Parameter` only for owner-less globals (noise sigma,
   sim speed); anything an object owns gets a control on its selection card.
   A `Probe` for every quantity worth a curve and every number the paper
   will quote; `Plot2D` bottom-right, one quantity per strip.
4. **Scenarios.** Named, scripted, imperative setup in `script`; the lab
   cold-opens into one; applying one resets clock + RNG.
5. **Conventions block** — generated (below). A build lab gets the whole
   board layer: `Board`, `BoardInput`, `BoardWires3D`, `PartPlacer`,
   `BoardPalette`, `PartCard`, `BoardOverlay`; the kit supplies a part spec,
   a solver and a part visual, nothing else.
6. **Theme + i18n from the first commit** (design rules below).
7. **Flow(s)** with a real learner task and `expect`s on the key steps.
8. **Verify** (below), then **paper + board last**, from committed records.

## The conventions contract

The root is `id: root` and implements `scenarios()`, `applyScenario(n)`,
`labInfo()`, `flagInfo()`, `viewState()` / `applyViewState(s)`,
`flowActions()`, `flows()`, `startFlow(id)`, `frameAll()`,
`frameSelection()`; it holds a `SimClock`, a `ScenarioSet` it cold-opens
into, `LabKeys` + `LabHelp` with the lab's own keys as data, and calls
`LabLang.register` for the kit's vocabulary and then the lab's copy
**before** the first `applyScenario`. `lab-new` writes all of it; its
template is a lab that ctest boots (`lab_new_boot_<kind>`), so it cannot rot.
`tools/lab-new/README.md` has the tokens.

- **Every state change is a named verb in `flowActions()`.** The UI, the
  flows and an agent's `eval` all go through the same verbs; no path mutates
  state behind them.
- **`viewState()` carries the user's whole place** — camera, selection,
  toggles, and for a build lab the entire built artifact. A measurement in
  hand is never in it. On restore the loader applies the scenario first
  (resets clock + RNG), then `applyViewState`; the user's own state wins over
  the preset. A reload is therefore not a fresh start (`pitfalls.md`,
  *Determinism*).
- **A part's state is set on its selection card**; operating it in the
  scene is a shortcut gated on selection.
- `labInfo()` stays language-neutral: ids and types, never display labels.

## Design rules

- Only `LabTheme` tokens, for size and spacing as much as colour:
  `font.pixelSize: LabTheme.fontBody`, `LabTheme.spaceL`, `LabTheme.px(280)`.
  **A bare `pixelSize:` or pixel width in a lab is a bug.**
- Ink over a fill is `LabTheme.inkOn(fill)`, never a literal; a colour that
  must survive both themes moves with `LabTheme.step(c, amount)`, never
  `Qt.darker()`. Verify every new lab in both themes and at two UI scales.
- No bare user-visible literal, ever: `LabLang.t("key")`, numbers through
  `LabLang.num(v, digits)` / `LabLang.qty(v, unit)`, never `toFixed`. Kernel
  chrome keys (`flow.*`, `keys.*`, `watch.*`, `rec.*`) are built in — never
  copy them into a lab. Narration keys are `flow.<flowId>.<stepKey>`.
- Text panels are width-capped and elide, against the neighbouring panel,
  not `root.width` (a translation runs ~25 % longer).
- Flat and glare-free: toon shading, `specularAmount: 0`, no IBL; lines lie
  flat (`Flat` + `depthBias`); areas are `Poly3D`; identity is printed onto
  parts (render-to-texture), real conventions (resistor colour code, IEC
  symbols) over decoration.
- Hover is a thin quiet outline; selection is a thick frame with a facing
  mark and a 2D card (`SelectionFrame3D`, `PartCard`). A watched object
  wears its curve's colour in the world and in the legend. Three or four
  semantic colours, from the named tokens.
- **Dual representation, one model**: the 3D scene shows what you built, an
  abstract panel (`MiniMap`) shows what it *is*, from the same data; `M`
  toggles it. One toggle that states the lesson (`V` labels every part).
- HUD slots: palette top-left · compass under it · abstract view bottom-left
  · monitor bottom-right · banner top-centre · hint bar bottom-centre
  (`HintBar { flow: …; rightGuard: monitor }`) · language, theme and scale
  switches top-right · parameters right. Every 3D lab stands on
  `LabStage3D`; every panel is a `LabPanel` (it fades in focus mode on its
  own — wire only what you built yourself with `visible: !LabView.focus`).
- **The left button is never the camera's.** `OrbitInput3D` declines it;
  RMB turns about the point under the cursor, middle pans, wheel zooms to
  the cursor, double-click focuses, held `Space` lends LMB to the view. A
  lab with nothing to build may set `panButtons` once; nothing flips at
  runtime. Never add a lab-local camera gesture. The `MouseArea` shape is in
  the generated `Sandbox.qml`.
- Instruments: one `InstrumentScale` per reading, faces only draw it; the
  belt (`InstrumentBelt`, one line inside the `View3D`) gives every lab a
  tape and a stopwatch; a new instrument is one file on
  `HandheldInstrument` with no gesture code in it.

## Canonical key map

Declared through `LabKeys` (so `LabHelp` on `?` documents it); a lab may add
keys, never reassign these. Letters stay physical across languages.

| key | meaning | owner |
|---|---|---|
| `1..9` | scenarios | lab |
| `C` / `E` / `R` / `Del` | clear / eraser / rotate / delete | lab |
| `V` | show values — the scene-wide value attribute in a build lab (off → each quantity → off), the readout panel in a continuous one | lab |
| `M` | abstract view — schematic or lane graph in a build/draw lab, the plot in a continuous one | lab |
| `Q` | watch / plot the selection | lab |
| `f` / `⇧F` | jump labels — type one to select in place / frame selection (plain `F` frames in a lab without `jump:`) | lab |
| `j` `k` / `h` `l` / `⏎` | walk the card's rows / adjust the focused one / operate the actuator — while something is selected | card |
| `H` / `P` | take the next instrument / keep (pin) its reading as a probe | belt |
| `Backspace` / `Esc` | undo a measured point / clear, then put the instrument away, cancel, leave | belt, flow |
| `T` | start / stop the (first) flow | flow |
| `Space` / `→` / `←` | next / next / back while a flow runs | flow |
| `Space` held | lends the left button to the camera while nothing narrates | camera |
| arrows, `WASD` / `Shift`+arrows / `+` `-` / `0` `Home` | travel / turn / zoom / reset view — `W A S D` are as reserved as the arrows | camera |
| `#` | grid mode | lab |
| `Tab` | focus mode (HUD away) | kernel |
| `Shift+R` | record a run | kernel |
| `Ctrl` `+` / `-` / `0` | text size | kernel |
| `?` | key map | kernel |

## Determinism and verification

Every lab: (a) all randomness from `SimClock` — visualization never consumes
the sim RNG stream (decorative jitter hashes stable inputs); (b) runs
correctly under the inspector's `time` pause/step; (c) exposes `labInfo()`.

**Run the gate first, then verify what it does not cover** — nothing in it
looks at a picture:

```bash
tools/lab-check/lab-check labs/<slug>                    # load, determinism, flows, strings, records, remarks
tools/lab-check/lab-check labs/<slug> --only flows       # while you work
ctest --preset default -R lab_check                       # every lab
```

Then, in order (clay-crew skill has the inspector protocol):

1. `qmllint` + `waitForRoot` after every edit round.
2. Determinism: `lab-check --only determinism`. Both runs need their own
   process and a clock paused before the measured root exists.
3. **Assertions over screenshots.** `eval` the quantity you changed; if the
   question is numeric (size, position, colour, count) query the scene —
   `clayrender … --dump lines=out.json`, `--project x,y,z`, `--pick x,y`. A
   screenshot answers "does this read to a human", nothing more, and is
   never the only evidence.
4. Drive the real input path (synthetic clicks/keys) once per feature —
   property pokes hide real bugs.
5. Kit JS: `node labs/kits/<kit>/<kit>.test.js`.
6. Every flow is a test:

   ```bash
   ./build/bin/clayrender labs/<lab>/Sandbox.qml --out /tmp/x.png \
       --paused --result - --eval 'Lab.runFlow("<flowId>")'
   ```

   The answer must read `"finished": true` with `unresolvedVerbs`,
   `failedTasks` and `failedExpects` empty. `--paused` is not optional.
7. Measure, never guess, anything with a numeric knob (shadows, fades):
   parameter sweep + pixel sampling.
8. Motion is judged over time: `clayrender --trace <expr> --trace-out
   <file>` samples per frame in one command; a whole lesson through the
   inspector's `trace` action. Ask the rig where a check wants yes/no:
   `rig.covers(points, margin, true)`.

`clayrender` is the default way to look at a lab (state in, picture or
answer out, exit codes 1/2/3 are failures); the dojo is for interaction,
hot-reload iteration and anything stateful. The whole option set —
`--set`/`--eval`/`--script` in command-line order, `--wait-for`, `--result`,
`--settle`, `--crop <objectName>`, `--prefs` — is
`docs/docs/manual/clayrender.md`; this skill does not repeat it.

## Numbers — from measurement to paper

- **Quote only what a record holds.** Every number in a paper names its
  `.labrec` in `records/`; a number you cannot get out of a record is a
  missing probe, not a licence to quote from the panel.
- Records come from **stepped** runs by the committed driver:
  `labs/<lab>/records/make.sh` (with `--verify`, which runs each scenario
  twice and `cmp`s). Any change to model, sensors or RNG consumption
  invalidates the records — rerun `make.sh` and re-read the table in the
  same commit.
- Figures come only from `figures/make.sh`, cropped by `objectName`, never
  downscaled, and no number is read off one.
- A question asked of a lab is a **study**: answerability first
  (`Parameter` / `Probe` / model-card claim, or a reduced question), then
  `tools/lab-sweep/lab-sweep <study-dir> --check`, `--dry-run`, run. Manifest
  and runner: `tools/lab-sweep/README.md`; the paper-side rules:
  `references/triad.md`.
